# Ren Prod / team-routing

Локальный независимый прототип. Python 3.11+ stdlib + SQLite + HTML/JS. Внешняя CRM не подключена. Соседние src/crm-prototype и src/shooting-landing не изменяются.

## Запуск на Mac

Из этой папки:

```sh
python3 control.py start
python3 control.py status
python3 control.py stop
python3 -m unittest -v test_core.py
```

Ручной запуск: `python3 server.py --port 8766` и отдельно `python3 bot.py`. Не запускайте bot.py параллельно с control.py start: процесс защищён файловой блокировкой. Перезапуск: stop, затем start. LaunchAgent не устанавливается; после перезагрузки нужен ручной запуск. Остановка Mac/потеря сети прерывает работу. Это не постоянный сервер.

- http://127.0.0.1:8766/ — recruitment, FAQ, вопрос (локальное сохранение).
- /join — веб-анкета без обязательного Telegram.
- /client — визитка и копируемый шаблон первого контакта; отправки нет.
- /brief — мобильный бриф съёмка/монтаж/генерация/мероприятие, черновик для сметы.
- /panel — доверенный локальный пульт владельца: анкеты, проверка квалификации, занятость, подбор, отклики, назначение, приглашения менеджеру, workspace, очередь и брифы.
- `?lang=en` — английская публичная версия; RU/EN каталоги в locales/. Бот, пульт, динамические ошибки/сообщения сохранения пока RU. ES/FR не переведены. Валюты не конвертируются; демонстрационный подбор только RUB. Это международная основа, не готовая международная CRM.

Тема в CSS custom properties --rp-bg, --rp-surface, --rp-text, --rp-accent, --rp-border, --rp-font. Локальная копия; автоматической синхронизации с другими подпроектами нет. Шрифты системные, CDN нет.

## Реальный Telegram

Бот @RENNPROD_bot: открыть и отправить `/start`. Анкета пошаговая, варианты задаются кодами из справочников. `/profile` — статус, `/cancel` — удалить незавершённый черновик; готовый профиль остаётся. `/blocks` — занятые интервалы и инструкция. `/busy 2026-12-02T10:00|2026-12-02T12:00|Europe/Moscow` добавляет частичный день. `/unblock ID` отменяет блокировку; изменение через отмену и добавление либо пульт. Команды доступны только владельцу Telegram-профиля в private chat. Пересечения с назначениями/жёсткой занятостью отклоняются. Не запрашиваем личный внешний календарь.

Секрет читается программно только из корневого .env, TELEGRAM_BOT_TOKEN. Он не передаётся аргументом процесса и не печатается. Не публикуйте .env, data/, логи и скриншоты с контактами. data/ исключён локальным .gitignore. Предварительно проверяются getWebhookInfo и файловая блокировка; существующий webhook не удаляется. Регистрация отвечает только на входящие private messages. Нет рассылок, приглашений третьим лицам, исходящей доставки предложений или email. Исходящие ответы анкеты идут реальному инициатору.

SQLite — источник истины регистрации. Незавершённый диалог, offset и дедупликация updates сохраняются после перезапуска. Состояние анкеты и запись update применяются атомарно. При транспортном сбое ответ может повториться, но шаг анкеты дважды не применяется. Транспорт не даёт exactly-once отправки. Бот и сервер работают с одной базой; реальные Telegram-профили появляются в пульте после последнего согласия. Черновики ещё не являются готовыми специалистами.

## Проверка сценария

1. В пульте есть четыре явно демо-профиля и три тестовых заказа. Они не означают реальных людей/ставки.
2. Для `simple` включено владельцем автоназначение. «Подобрать» создаёт персональное предложение следующему проверенному кандидату. Подтверждение точных условий атомарно занимает место. Отказ/истечение ведут к следующему; без кандидатов место остаётся открытым.
3. Для `crew` параллельно собираются отклики по трём местам и приглашение менеджеру. Отклик ≠ назначение. До принятия руководства нельзя назначить состав. После принятия создаётся пространство, участники появляются только по назначению. Заполнение одной роли не закрывает остальные.
4. `unknown` сразу уходит в human_review; система не придумывает классификацию.
5. Создайте блокировку даты до подбора: пересекающийся кандидат исключится. Если блокировка появилась после предложения, подтверждение повторно проверит конфликт.
6. В workspace выбирайте неназначенного кандидата — серверная функция вернёт отказ. Участнику возвращается общий бриф без rate/fee/budget; finance лежит в private offer.
7. Локальный сервер автоматически вызывает tick каждые 30 секунд; «Обработать сроки» запускает его дополнительно. Рабочий дедлайн считает пн–пт 09–18 в timezone исполнителя; это тестовая политика, не утверждённый SLA. Праздники, DST ambiguity и индивидуальные расписания пока не реализованы. В production нужен отдельный надёжный worker вместо daemon thread локального HTTP-сервера.

## Границы безопасности и автоматизации

Сервер слушает только 127.0.0.1, раздаёт исключительно перечисленные маршруты, не корень проекта. Приватные архивы не обслуживаются. Есть origin check и случайный local-session header против случайных межсайтовых POST. Однако session встроен в локальную страницу: это доверенный стенд владельца, любой локальный пользователь страницы может использовать owner/actor и увидеть все профили/ставки. Демонстрационный выбор actor НЕ авторизация. Не публиковать и не туннелировать.

Production: настоящие server-side sessions, проверенные identities, роли/политики на КАЖДОМ endpoint; owner видит все финансы, manager только явно разрешённое бюджетное окно, specialist только свои предложения. Перед внешним запуском отдельная независимая проверка, резервные копии, удаление/retention/consent, audit log, HTTPS, rate limiting, CSRF и изоляция public/internal endpoints обязательны. Общий чат не должен принимать финансовые условия: сейчас структурированные ставки исключены из workspace; текстовое обсуждение доверяет явному подтверждению автора, автоматической гарантии отсутствия произвольной суммы в тексте нет.

Функции в core.py проверяют membership/offer actor и атомарность домена, но текущий HTTP API не устанавливает достоверную identity пользователя. Нельзя считать эти проверки production-ACL. Не включать финансовый manager-view посредством скрытия кнопок: нужно отдельное разрешённое серверное представление.

Контакты/квалификация раздельны: email обязателен как резерв; Telegram/телефон необязательны для web. Контактная верификация — будущая функция, не симулируется как успешная. Новая анкета непроверена; владелец вручную подтверждает квалификацию. Изменение профиля снимает проверку. Портфолио не доказывает квалификацию. Свободный календарь не доказывает доступность: подтверждаются конкретные условия.

Notification — outbox-симулятор: event_key UNIQUE, явный ack, timezone deadline, ручная смена канала, email fallback при tick. Реальные Telegram/email предложения не отправляются. Статус online не используется; молчание не означает блокировку. Повторный подбор не создаёт дублей той же версии. Отмена назначенной смены/replacement и редактирование заказа через UI пока не реализованы; contract требует новой версии условий и повторного подтверждения.

## Telegram architecture / официальная проверка 25.10.2026

Проверены https://core.telegram.org/bots/api и https://core.telegram.org/bots/features. createForumTopic создаёт тему внутри существующего чата; отдельной приватной командной комнатой тема forum-supergroup не становится. В просмотренном Bot API нет метода createChat для создания отдельной private group. Базовое пространство — CRM с membership. Telegram — уведомления и существующие выделенные группы после проверки состава/прав; создание/пул групп — отдельное решение, без userbot. Бот не начинает приватный разговор с не запустившим его пользователем.

Видео, Instagram владельца, реальные портфолио и клиентские кейсы не предоставлены; показаны честные placeholders без fake play. Добровольные взносы отложены: платежей и платного ранжирования нет.
